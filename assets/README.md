# Изображения и публикация

`assets/images` содержит только изображения, которые использует сайт сейчас.
У каждой используемой ссылки выбран самый маленький из проверенных вариантов
с одинаковыми пикселями, размерами, цветом и прозрачностью. Дополнительное
сжатие с потерями не применяется. Иконки браузера сохраняют требуемые PNG/ICO
форматы. JPG и прозрачный PNG одной планировки не считаются эквивалентными.

```text
assets/
  images/                          # Только файлы для сайта
    shared/                        # Логотип, иконки, карта, заглушки
    site/                          # Фотографии сайта
    projects/
      tchaikovsky/
        apartments/{plans,previews}/
        floors/{backgrounds,overlays}/
        ui/
      vivaldi/
        apartments/{plans,previews}/
        floors/backgrounds/
  manifests/production-images.json # Проверяемый список публичных файлов
  sources/                         # Локальные материалы; исключены из Git
    originals/                     # Исходники и альтернативные форматы
    project-exports/                # Дополнительные экспорты квартир
    projects/tchaikovsky/illustrator/
    unavailable-apartments.zip      # Изображения и данные 95 недоступных квартир
    catalogs/before-production.json # Полные каталоги до разделения
    data/                          # Исходные данные этажей и инструкции
    legacy-code/                   # Неиспользуемые JS/CSS и прежняя миграция
    generated/                     # Результаты обработки для ручной проверки
```

Все 403 записи Tchaikovsky и 60 записей Vivaldi сохранены. Недоступные квартиры
остаются серыми и не открываются на плане; их runtime-поля изображений используют
общую заглушку. Оригинальные изображения и ссылки сохранены в локальном ZIP и
полном снимке каталога. В ZIP проверены CRC и SHA-256 каждого файла.

## Сборка для публикации

```sh
python3 -B scripts/generate-home-routes.py
python3 -B scripts/build-production.py --check
node --test tests/*.test.mjs
python3 -B scripts/build-production.py
python3 -B scripts/build-production.py --archive dist.zip
```

Команда без параметров создаёт `dist/`; `--archive` создаёт готовый `dist.zip`
непосредственно из проверенного списка файлов. Загружать на сервер нужно содержимое
этой папки или ZIP: страницы сайта и маршрутов разделов, используемые JS/CSS, шрифты, видео и файлы
из проверенного списка изображений. Исходники, ZIP, архив, тесты, инструменты,
документация, манифесты проверки и служебные файлы в сборку не попадают.
Непустая папка результата не перезаписывается; для повторной сборки укажите
новую папку через `--output` или предварительно перенесите прежний результат.
ZIP также не перезаписывается. Файлы Finder и прочие служебные файлы не включаются
в ZIP, даже если операционная система добавит их в локальную папку `dist` позже.

## Маршруты главной

Адреса `/about-project/`, `/features/`, `/infrastructure/`, `/financing/`,
`/contact/` и `/request-callback/` открывают соответствующие разделы главной
без хэштега. У каждого адреса есть статическая HTML-страница, поэтому обновление
и прямое открытие работают на GitHub Pages, в том числе внутри `/evolution/`.
Все страницы используют метаданные и canonical главной.

Источник содержимого — `index.html`, карта маршрутов — `config/site-routes.json`.
После изменения главной или карты запустите `scripts/generate-home-routes.py`:
он обновит страницы маршрутов и `js/home-routes.js`. Генерируемые HTML нужно
коммитить вместе с исходной главной. Сборка отклоняет устаревшие копии;
отдельная проверка: `python3 -B scripts/generate-home-routes.py --check`.

При входе на главную и её маршруты удаляются только параметры фильтра каталога
(`house`, `type`, `floor`, `property`, `view`, `kvadrati-od`, `stanovi-do`).
UTM и другие независимые параметры сохраняются. Ссылки самого каталога с фильтрами
продолжают работать. Прежние `?section=...` и хэштеги известных разделов
преобразуются в соответствующие маршруты.

Выбранный дом сохраняется отдельно от URL в `sessionStorage` текущей вкладки
с ключом для текущей папки сайта. Определение дома находится в
`js/house-context.js`: контекст объекта имеет приоритет перед текущим каталогом,
URL и последним сохранённым выбором. Общая заявка и запрос цены включают
`Objekat: Tchaikovsky` или `Objekat: Vivaldi` в CRM-поле `COMMENTS`.
Если посетитель главной ещё не выбрал дом, общая заявка содержит
`Objekat: Nije izabran`.

## Очередь загрузки изображений

Бинарные изображения и их качество остаются прежними. У фотографий в HTML
заданы фактические размеры и асинхронное декодирование. Первый экран главной
загружается сразу, основная фотография имеет высокий приоритет; нижние блоки
используют нативную отложенную загрузку. Из 8,24 МБ уникальных изображений
главной 5,43 МБ относятся к этим нижним блокам. Браузер может заранее подгружать
близкие к экрану изображения в зависимости от соединения.

Видео 13,04 МБ получает источник только при появлении в видимой области;
вне экрана и в скрытой вкладке воспроизведение останавливается. При первом
появлении возможна короткая буферизация. Сборка учитывает отложенные `data-src`
у `video` и `source`, поэтому файл включается в готовый ZIP.

В сетке каталогов первая строка карточек имеет высокий приоритет, остальные
изображения остаются отложенными. Фоновые планы загружаются после выбора
режима плана: сетка Tchaikovsky больше не запрашивает начальный SVG/фон
на 1,22 МБ, а сетка Vivaldi — семь фонов на 1,56 МБ. На плане Vivaldi
загружается только выбранный этаж; прежний остаётся виден до декодирования
нового. Загруженные этажи используются повторно, неуспешные запросы можно
повторить. Полные планировки квартир по-прежнему загружаются при выборе
объекта, а модальное окно ждёт готовности изображения.

## Обновление изображений

Инструменты обработки читают локальные исходники, а результаты записывают в
`assets/sources/generated`. Они не меняют публичные изображения и runtime-код.
После проверки качества нужно перенести выбранный результат в `assets/images`,
обновить готовые URL и список `production-images.json`, затем повторить сборку.
Восстановление недоступной квартиры начинается с распаковки её файлов из ZIP;
данные и прежние ссылки находятся в `catalog.json` внутри архива.
