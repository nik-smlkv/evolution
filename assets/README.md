# Изображения и публикация

`assets/images` содержит только изображения, которые использует сайт сейчас.
У каждой используемой ссылки выбран самый маленький из проверенных вариантов
с одинаковыми пикселями, размерами, цветом и прозрачностью. Дополнительное
сжатие с потерями не применяется. Иконки браузера сохраняют требуемые PNG/ICO
форматы. JPG и прозрачный PNG одной планировки не считаются эквивалентными.

```text
assets/
  images/                          # Только файлы для сайта
    shared/                        # Логотип, иконки, карта, заглушки
    site/                          # Фотографии сайта
    projects/
      tchaikovsky/
        apartments/{plans,previews}/
        floors/{backgrounds,overlays}/
        ui/
      vivaldi/
        apartments/{plans,previews}/
        floors/backgrounds/
  manifests/production-images.json # Проверяемый список публичных файлов
  sources/                         # Локальные материалы; исключены из Git
    originals/                     # Исходники и альтернативные форматы
    project-exports/                # Дополнительные экспорты квартир
    projects/tchaikovsky/illustrator/
    unavailable-apartments.zip      # Изображения и данные 95 недоступных квартир
    catalogs/before-production.json # Полные каталоги до разделения
    data/                          # Исходные данные этажей и инструкции
    legacy-code/                   # Неиспользуемые JS/CSS и прежняя миграция
    generated/                     # Результаты обработки для ручной проверки
```

Все 403 записи Tchaikovsky и 60 записей Vivaldi сохранены. Недоступные квартиры
остаются серыми и не открываются на плане; их runtime-поля изображений используют
общую заглушку. Оригинальные изображения и ссылки сохранены в локальном ZIP и
полном снимке каталога. В ZIP проверены CRC и SHA-256 каждого файла.

## Сборка для публикации

```sh
python3 -B scripts/build-production.py --check
node --test tests/*.test.mjs
python3 -B scripts/build-production.py
python3 -B scripts/build-production.py --archive dist.zip
```

Команда без параметров создаёт `dist/`; `--archive` создаёт готовый `dist.zip`
непосредственно из проверенного списка файлов. Загружать на сервер нужно содержимое
этой папки или ZIP: только четыре HTML-страницы, используемые JS/CSS, шрифты, видео и файлы
из проверенного списка изображений. Исходники, ZIP, архив, тесты, инструменты,
документация, манифесты проверки и служебные файлы в сборку не попадают.
Непустая папка результата не перезаписывается; для повторной сборки укажите
новую папку через `--output` или предварительно перенесите прежний результат.
ZIP также не перезаписывается. Файлы Finder и прочие служебные файлы не включаются
в ZIP, даже если операционная система добавит их в локальную папку `dist` позже.

## Обновление изображений

Инструменты обработки читают локальные исходники, а результаты записывают в
`assets/sources/generated`. Они не меняют публичные изображения и runtime-код.
После проверки качества нужно перенести выбранный результат в `assets/images`,
обновить готовые URL и список `production-images.json`, затем повторить сборку.
Восстановление недоступной квартиры начинается с распаковки её файлов из ZIP;
данные и прежние ссылки находятся в `catalog.json` внутри архива.
